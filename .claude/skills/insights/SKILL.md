# 인터뷰에서 인사이트 뽑기 (Discover)

`00_inputs/interviews/` 의 모든 인터뷰 기록과 `00_inputs/product-brief.md` 를 읽고 `01_discover/insights.md` 를 만듭니다.

## 규칙

- 인터뷰에 **실제로 나온 말**만 근거로 씁니다. 각 인사이트에 참가자 번호와 짧은 인용을 붙입니다. 지어내지 않습니다.
- 인사이트는 "사용자가 원하는 기능"이 아니라 **"어떤 상황에서 무엇 때문에 막히는가"** 로 씁니다.
- 한 사람만 말한 것과 여러 사람이 말한 것을 구분합니다.

## 결과 형식 (01_discover/insights.md)

```markdown
# 인사이트 카드

## 사용자와 상황
- 누가, 언제, 어디서 이 플로우를 쓰는가 (3줄 이내)

## 인사이트
| # | 막히는 순간 | 왜 문제인가 | 근거 (참가자 · 인용) | 몇 명 |
|---|---|---|---|---|

## 성공 기준 (사용자 입장에서 "잘 됐다"는 무엇인가)
-

## 아직 모르는 것 (추가로 물어볼 질문 3개)
1.
```

## 충분성 점검 (마지막에 스스로 확인하고 결과를 사용자에게 보고)

- [ ] 사용자와 상황이 구체적인가
- [ ] 막히는 순간이 3개 이상이고 모두 근거 인용이 있는가
- [ ] 성공 기준이 관찰 가능한 문장인가
- [ ] 아직 모르는 것을 적었는가

하나라도 비면 무엇이 부족한지 사용자에게 말합니다. 끝나면 다음 단계로 `/interview-me` 를 안내합니다.
