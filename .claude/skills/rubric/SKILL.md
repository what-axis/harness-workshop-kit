# 채점표 완성하기 (Deliver)

`04_deliver/rubric.md` 는 반쯤 채워진 채점표입니다. 1~5번은 어디서나 통하는 공통 항목이고, 6~10번이 비어 있습니다. 빈칸을 아래 재료로 채웁니다.

- `01_discover/my-criteria.md` 의 "가장 중요한 세 가지" → 6, 7번 (내 판단 기준)
- `02_define/brief.md` 의 검증 항목 → 8, 9번 (가설 검증)
- `04_deliver/qa-checklist.md` 에서 이 플로우에 가장 치명적인 예외 상태 → 10번

## 좋은 항목의 조건

항목마다 아래 네 가지를 통과해야 합니다. 통과하지 못하면 문장을 고칩니다.

1. **관찰 가능:** 화면이나 측정값을 보고 판단할 수 있다. ("사용성이 좋다"는 불가)
2. **하나만 묻는다:** "그리고"로 두 가지를 묶지 않는다.
3. **0점과 10점이 그려진다:** 최악과 최선의 화면이 떠오른다.
4. **확인 방법이 정해져 있다:** 측정(기계) / 화면 읽기(AI) / 직접 보기(사람)

## 진행

1. 빈칸 다섯 개의 초안을 채워 사용자에게 **표로 보여 줍니다.** 아직 파일에 쓰지 않습니다.
2. 사용자에게 묻습니다: 빼거나 바꿀 항목이 있는지, 사람이 직접 봐야 하는 항목은 무엇인지.
3. 확정되면 `04_deliver/rubric.md` 에 반영합니다. 맨 아래 "승인" 줄에 날짜와 "사람 승인"을 적습니다.
4. 항목이 10개가 아니어도 됩니다. 다만 합계가 100점이 되도록 배점을 맞춥니다.

## 흔한 실수

- AI에게 항상 만점을 받는 항목: "일관성이 있다", "직관적이다". 숫자나 화면 요소로 바꿉니다.
- 디자이너만 알 수 있는 취향 항목: 남겨도 되지만 담당을 "사람"으로 둡니다.

끝나면 오후 루프 시작 방법을 안내합니다: 터미널에서 `claude --agent director` 로 다시 들어오거나, 지금 대화에서 `.claude/agents/director.md 의 역할로 루프를 시작해줘` 라고 말하기.
