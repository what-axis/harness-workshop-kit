# 브리프와 가설 만들기 (Define)

`01_discover/insights.md`, `01_discover/my-criteria.md`, `00_inputs/product-brief.md` 를 읽고 `02_define/brief.md` 를 만듭니다. 없는 파일이 있으면 어떤 스킬로 만들 수 있는지 알려 주고 멈춥니다.

## 규칙

- 한 장을 넘기지 않습니다. 디자이너 에이전트가 이 문서만 읽고 화면을 만들 수 있어야 합니다.
- 가설은 **"화면이 ~하면 사용자는 ~할 것이다"** 형식으로 2~3개만. 인사이트 번호를 근거로 답니다.
- 가설마다 **"이 가설이 맞으려면 화면에 무엇이 보여야 하는가"** 를 검증 항목으로 씁니다. 이 항목이 오후에 채점표로 들어갑니다. 눈으로 확인할 수 있는 문장이어야 합니다.
- 초안을 만든 뒤 사용자에게 가설이 맞는지 묻고, 고쳐 달라는 대로 고칩니다.

## 결과 형식 (02_define/brief.md)

```markdown
# 화면 브리프

## 문제 정의
- 누가:
- 언제:
- 무엇 때문에 막히는가:
- 해결하지 않으면:

## 목표 (이 플로우가 끝났을 때 사용자의 상태)

## 핵심 플로우 (단계 3~5개)
1.

## 만들 화면 (정상 상태 기준, 2~4장)
| 번호 | 화면 | 이 화면에서 반드시 보여야 하는 것 |
|---|---|---|

## 가설과 검증 항목
| 가설 | 근거 인사이트 | 화면에서 확인할 것 (검증 항목) |
|---|---|---|

## 제약
- 디자인 규칙: DESIGN.md
- 범위 밖: (이번에 만들지 않는 것)
```

## 문제 정의 점검 (끝나고 스스로 확인해 보고)

- [ ] 누가, 언제가 한 사람의 한 장면으로 그려지는가
- [ ] "해결하지 않으면"이 사용자에게 생기는 손해로 적혔는가
- [ ] 검증 항목이 모두 화면을 보고 예/아니오로 답할 수 있는가

끝나면 다음 단계(Develop)로 아래 한 줄을 안내합니다.
`designer 에이전트로 02_define/brief.md 의 화면을 만들어줘. 아직 검증은 하지 마.`
