# 디자인 시스템을 DESIGN.md 로 바꾸기

사용자가 준 자료($ARGUMENTS, 또는 대화에 붙여 넣은 내용, `00_inputs/` 에 넣은 파일)를 읽고, 지금 `DESIGN.md` 와 **같은 목차**로 새 DESIGN.md 초안을 만듭니다.

## 규칙

- 기존 `DESIGN.md` 는 덮어쓰기 전에 `DESIGN.sample.md` 로 복사해 둡니다.
- 목차는 그대로: 0 브랜드 한 줄 / 1 컬러 토큰 / 2 타이포그래피 / 3 간격과 모서리 / 4 컴포넌트 규격 / 5 상태 규칙 / 6 카피 톤 / 7 금지 사항 / 8 구현 규칙
- **1 컬러 토큰은 반드시 표로, HEX 6자리로** 적습니다. 측정 스크립트가 이 표를 읽습니다.
- 자료에 없는 값은 지어내지 않고 `(확인 필요)` 로 남긴 뒤, 끝에 사용자에게 물어볼 질문 목록으로 모읍니다.
- 느낌 표현("세련된", "친근한")은 숫자나 금지 사항으로 바꿉니다. 바꿀 수 없으면 6 카피 톤이나 0 브랜드 한 줄에만 둡니다.
- 보조 글자색이 바탕색 위에서 4.5:1 이 되는지 계산해 보고, 안 되면 사용자에게 알립니다.

## 피그마에서 가져오는 가장 쉬운 방법 (사용자에게 안내)

1. 피그마 Variables 패널이나 스타일 목록을 텍스트로 복사해 붙여 넣기
2. 컴포넌트 문서 페이지를 스크린샷으로 찍어 `00_inputs/` 에 넣기
3. Figma MCP 가 연결되어 있다면 파일 링크를 주고 변수와 컴포넌트를 읽게 하기

## 회사 자료를 다룰 때

- 대외비 자료라면 회사가 허용한 계정과 환경에서만 진행하도록 먼저 확인합니다.
- 실습 중에는 색 이름과 수치만 가져오고, 미공개 제품 화면은 넣지 않도록 권합니다.
