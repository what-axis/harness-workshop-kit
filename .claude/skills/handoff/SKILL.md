# 개발 전달 문서 만들기

아래 파일을 읽고 `04_deliver/handoff.md` 를 만듭니다. 없는 파일은 "없음"이라고 적고 넘어갑니다. 내용을 지어내지 않습니다.

- `03_develop/screens/*.html`, `03_develop/shots/`
- `DESIGN.md`, `02_define/brief.md`
- `04_deliver/rubric.md`, `04_deliver/log.md`, 가장 최근의 `review-loop*.md` 와 `qa-loop*.md`, `04_deliver/reports/measure.md`

## 문서 구성

1. **한 줄 요약**: 무엇을 위한 화면 묶음인지, 최종 점수와 루프 횟수
2. **화면 목록**: 파일, 어떤 상태인지, 스크린샷 경로, 이 화면으로 들어오는 조건
3. **상태 지도**: 플로우 단계 × 상태(정상, 처리 중, 성공, 빈 상태, 오류, 불가) 표. 화면이 있는 칸은 파일 이름, 의도적으로 뺀 칸은 이유
4. **쓰인 토큰과 컴포넌트**: DESIGN.md 의 어떤 토큰과 규격을 썼는지. 새로 생긴 것이 있으면 따로 표시
5. **검증 기록**: 기계 측정 결과, 채점표 항목별 최종 점수, 점수 변화
6. **사람이 확인한 것과 아직 확인하지 못한 것**: 리포트의 "사람 확인 필요" 항목을 그대로 옮기고 확인 여부를 적을 칸을 둠
7. **개발자에게 묻고 싶은 것**: 화면만으로 정할 수 없는 것. 예: 재고 확인 시점, 오류 응답 종류, 로그인 만료 처리
8. **이 화면은 HTML 시안입니다**: 실제 컴포넌트 이름과 다를 수 있다는 안내와, 맞춰야 할 이름 대응표 자리

마지막에 사용자에게 문서 경로를 알려 주고, 7번 항목 중 지금 답할 수 있는 것이 있는지 물어봅니다.
