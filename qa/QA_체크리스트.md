# QA 케이스 체크리스트 — 모두의회의실

QA 에이전트가 이 목록을 렌즈로 화면과 플로우를 훑는다. 목적은 두 가지: ① 각 화면에 필요한 **상태·엣지 케이스**가 다뤄졌는지, ② 플로우에 **누락된 화면**("이 화면 없는데요?")이 있는지.

## 1. 상태 케이스 — 화면마다 물어볼 것

| 상태 | 질문 | 이 프로젝트의 예 |
|---|---|---|
| 빈 상태 | 데이터가 0개면 무엇이 보이는가 | 조건에 맞는 회의실 0개, 내 예약 0건 |
| 로딩 | 데이터 오는 동안 무엇이 보이는가 | 목록·슬롯 로딩 (스켈레톤, DESIGN.md §5) |
| 오류 | 실패하면 무엇이 보이고 어떻게 복구하는가 | 네트워크 실패, **예약 충돌(이미 선점됨)** — 입력 조건은 유지되는가 |
| 권한 없음 | 왜 안 되는지 설명하는가 | 세미나실(팀장 이상), 동시 3건 초과, 2시간 초과 |
| 부분 데이터 | 일부만 있으면 어떻게 보이는가 | 사진 없는 회의실, 장비 정보 미등록 |
| 시간 경계 | 시간이 흐르면 어떻게 되는가 | 보던 슬롯이 지나감, 자정 근처, 오늘 슬롯 마감 |

## 2. 엣지 케이스 — 데이터를 극단으로

- 긴 텍스트: 회의 제목 60자, 회의실 이름이 카드 폭 초과 → 말줄임 처리?
- 많은 데이터: 회의실 12개 전부 표시, 내 예약 3건 만석
- 최소 데이터: 필터 결과 1개일 때 레이아웃 유지?
- 연속 동작: 예약 버튼 연타 → 중복 예약 방지 표시?
- 뒤로 가기: 슬롯 선택 중 이탈 후 복귀 시 선택 유지?

## 3. 누락 화면 탐지 — 플로우에 이 질문들을

1. 모든 버튼·링크의 목적지 화면이 존재하는가 (예: "내 예약 보기" → **내 예약 목록 화면 있는가?**)
2. 모든 상태의 '반대편' 화면이 있는가 (예약 완료가 있으면 → **예약 실패는?** / 체크인 안내가 있으면 → **체크인 화면은?** / 자동 취소되면 → **취소 알림은?**)
3. 되돌리는 길이 있는가 (**예약 취소·변경 화면은?**)
4. 정책이 화면으로 존재하는가 (기획서 §6의 각 정책이 사용자에게 언제 어떻게 보이는가)
5. 첫 방문자가 보는 화면이 있는가 (온보딩/빈 홈)

## 4. QA 리포트 형식 (QA 에이전트용)

```
## 화면별 케이스 점검
- [화면명] 상태 6종 각각: 처리됨 / 미처리(근거) / 해당 없음(이유)

## 누락 화면 목록 (우선순위순)
- P1(출시 불가급) / P2(출시 주 보완) / P3(백로그)
- 각 항목: 어떤 사용자 행동에서 드러나는지 1줄 시나리오

## 보완 제안
- 이번 반복에서 만들 화면 1~2장 지정 (P1부터)
```

근거 없는 지적 금지 — 반드시 "어느 화면의 어느 요소/플로우의 어느 지점"인지 특정한다.
