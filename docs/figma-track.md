# 피그마를 연결할까, 말까

이 키트는 피그마 없이 끝까지 갈 수 있게 만들었습니다. 피그마를 연결하면 두 군데가 편해집니다. 규칙을 읽어 오는 입구와, 결과를 캔버스로 돌려보내는 출구.

조회 기준일: 2026-11-22. 피그마의 요금제와 베타 조건은 자주 바뀝니다.

## 두 트랙

| | 비연결 트랙 (기본) | 연결 트랙 (선택) |
|---|---|---|
| 규칙 가져오기 | 세 가지 중 하나 → `/design-md`. ① 피그마 변수와 스타일을 복사해 붙여 넣기 ② 스크린샷 ③ 공개된 서비스 주소에서 읽기(`node scripts/site-tokens.mjs 주소`) | 에이전트가 피그마 파일의 변수, 컴포넌트, 스타일을 직접 읽는다 |
| 화면 만들기 | HTML 화면. 브라우저와 스크린샷으로 확인 | 같음 |
| 검증 | 측정, 리뷰어, QA, 루프 | 같음 |
| 결과 돌려주기 | 갤러리와 전달 문서 `/handoff` | 통과한 화면을 피그마 캔버스에 편집 가능한 레이어로 보낸다 |
| 필요한 것 | 없음 | 피그마 계정, 원격 MCP 서버 연결, 회사의 연결 허용 |
| 막힐 수 있는 곳 | 없음 | 로그인 인증, 좌석 종류, 회사 보안 정책 |

검증은 두 트랙이 똑같습니다. 피그마는 입구와 출구일 뿐이고, 하네스는 가운데에 있습니다.

### 비연결 트랙에서 배포된 화면을 그대로 쓰는 법

스크린샷 대신 서비스 주소를 줄 수 있습니다. 키트의 `scripts/site-tokens.mjs` 가 그 화면을 열어 실제로 쓰인 색, 글자 크기, 모서리, 간격, 버튼 크기를 세어 `01_discover/site-tokens.md` 로 남깁니다.

```
https://(우리 서비스 주소) 화면의 겉모습 값을 읽어줘(node scripts/site-tokens.mjs). 읽은 값으로 DESIGN.md 의 1~4번을 어떻게 바꿀지 표로 제안해줘. 아직 고치지는 마.
```

- 읽히는 것은 겉모습(1~4번)뿐입니다. 빈 상태, 오류, 문구 규칙은 화면 한 장에 보이지 않으므로 직접 채웁니다. 공개 DESIGN.md 84개가 같은 이유로 상태와 문구가 비어 있었습니다.
- 로그인 뒤의 화면은 읽지 못합니다. 그런 화면은 스크린샷이나 피그마 변수로 보충합니다.
- 데스크톱 화면이라면 끝에 `--desktop` 을 붙입니다.

## 어느 쪽으로 갈까

- 회사가 외부 AI 도구와 피그마 연결을 아직 허용하지 않았다 → 비연결
- 디자인 시스템이 피그마 변수로 잘 정리돼 있다 → 연결하면 1층(겉모습)이 정확해진다
- 변수가 정리돼 있지 않다 → 연결해도 읽어 올 것이 없다. 비연결로 DESIGN.md 부터
- 통과한 화면을 팀이 피그마에서 이어서 다듬어야 한다 → 연결

오늘은 모두 비연결로 한 사이클을 끝내고, 연결은 시연과 선택 실습으로 다룹니다.

## 연결하는 법 (Claude 앱)

Claude 앱의 설정에서 커넥터 목록을 열어 Figma 를 연결하고 피그마 계정으로 로그인합니다. 연결한 뒤 Code 탭에서 아래 한 줄로 확인합니다.

```
피그마가 연결돼 있는지 확인하고, 연결된 계정과 좌석 종류를 알려줘.
```

Code 탭에서 피그마 도구가 보이지 않으면 Code 탭의 플러그인 목록에서 Figma 플러그인을 설치하거나, 아래 터미널 방법을 씁니다.

## 연결하는 법 (터미널의 Claude Code)

가장 쉬운 방법은 플러그인 설치입니다. 서버 설정과 피그마가 만든 스킬이 함께 들어옵니다.

```
claude plugin install figma@claude-plugins-official
```

플러그인을 쓸 수 없으면 서버만 직접 추가합니다.

```
claude mcp add --transport http figma https://mcp.figma.com/mcp
```

그다음 Claude Code 를 새로 시작하고 `/mcp` 에서 figma 를 골라 Authenticate, 브라우저에서 Allow access.

알아 둘 것:

- 원격 서버(`mcp.figma.com`)만 캔버스에 쓸 수 있습니다. 데스크톱 앱 서버는 읽기만 됩니다.
- 캔버스에 쓰기는 베타이고 지금은 무료입니다. 피그마는 나중에 사용량 기준 유료 기능이 된다고 밝혔습니다.
- 드래프트 밖의 파일에 쓰려면 Full 좌석이 필요합니다.
- 파일 링크는 프레임을 고른 뒤 "선택 영역 링크 복사"로 만든 링크가 가장 정확합니다.

## 프롬프트

읽어 오기 (입구):

```
이 피그마 파일의 변수와 텍스트 스타일을 읽어서 DESIGN.md 의 컬러 토큰 표와 타이포그래피 표를 채워줘. 토큰 이름은 피그마 변수 이름을 그대로 쓰고, 값이 없는 칸은 비워 두고 나에게 물어봐. (피그마 링크)
```

```
이 피그마 파일에서 버튼, 입력창, 칩, 바텀시트 컴포넌트의 변형과 크기를 읽어서 DESIGN.md 의 컴포넌트 규격 표를 고쳐줘. 고치기 전에 바뀌는 줄을 먼저 보여줘. (피그마 링크)
```

돌려보내기 (출구):

```
03_develop/screens 의 최종 화면을 피그마로 보내줘. 새 파일에 화면마다 프레임 하나씩, 편집 가능한 레이어로. 끝나면 파일 링크를 알려줘.
```

```
피그마로 보낸 프레임이 우리 라이브러리의 컴포넌트와 변수를 쓰고 있는지 확인하고, 하드코딩된 색이나 떨어진 컴포넌트가 있으면 표로 알려줘. 고치지는 마.
```

## 보낸 화면을 우리 컴포넌트로 바꿔 끼우려면

에이전트가 캔버스에 새로 그린 버튼은 우리 라이브러리의 버튼이 아닙니다. 세 가지 방법이 있고, 아래로 갈수록 정확합니다.

1. **보낼 때 먼저 찾게 합니다.** "새로 그리기 전에 우리 라이브러리에서 같은 컴포넌트와 변수를 찾아서 쓰고, 없는 것만 새로 그려줘"라고 시킵니다. 에이전트가 라이브러리를 검색해 인스턴스로 놓습니다.
2. **이름 대응표를 적어 둡니다.** DESIGN.md 의 컴포넌트 규격에 "피그마 이름 / 코드 이름" 두 열을 둡니다. 이름이 다르면 에이전트가 같은 것인지 알지 못합니다.
3. **Code Connect 로 묶습니다.** 피그마 컴포넌트와 코드 컴포넌트를 공식적으로 연결해 두는 피그마 기능입니다. 개발팀과 함께 하는 일이고, 한 번 해 두면 에이전트가 실제 코드 컴포넌트를 가리키게 됩니다. 널리 쓰이는 단계는 아닙니다. 공개 디자인 시스템 21곳을 조사한 자료에서 Code Connect 를 갖춘 곳은 3곳이었습니다.

```
03_develop/screens 의 최종 화면을 피그마로 보내줘. 새로 그리기 전에 (라이브러리 파일 링크) 에서 같은 컴포넌트와 변수를 찾아서 쓰고, 없는 것만 새로 그려줘. 새로 그린 것은 목록으로 알려줘.
```

## 연결했을 때 조심할 것

- **쓰기는 드래프트에서 먼저.** 팀 파일에 바로 쓰게 하지 않습니다.
- **대외비 파일.** 에이전트가 읽은 내용은 모델로 전송됩니다. 회사가 허용한 계정과 요금제인지 먼저 확인합니다.
- **이름이 어긋난 곳.** 피그마 속성 이름과 코드 속성 이름이 다르면 에이전트가 새 컴포넌트를 지어냅니다. 대응표를 DESIGN.md 나 스킬에 적어 둡니다.
- **주석의 의도.** "모바일에서는 세로로"처럼 주석에만 있는 의도는 놓치기 쉽습니다. 오토 레이아웃처럼 파일 구조로 드러내면 읽힙니다.

## 피그마 안의 에이전트와는 무엇이 다른가

피그마도 캔버스 안에서 일하는 자체 에이전트와 스킬을 내놓았습니다. 캔버스에서 바로 컴포넌트를 만들고 일괄 수정하기에 좋습니다. 이 키트의 방식은 캔버스 밖에서 화면을 코드로 만들고 **기준으로 검증한 뒤** 통과한 것만 캔버스로 보내는 쪽입니다. 둘은 경쟁이 아니라 앞뒤로 이어 쓸 수 있습니다.
