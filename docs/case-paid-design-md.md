# 사례: 유료 DESIGN.md 를 직접 받아 진단해 보니

getdesign.md 의 Private DESIGN.md(39달러, 한 번 결제)를 사서, 강사의 회사 사이트 what-axis.com 을 분석 대상으로 요청했습니다. 받은 파일을 이 키트의 진단 도구로 쟀습니다.

측정일: 2026-11-24. 받은 파일의 원문은 이 저장소에 넣지 않았습니다. 재배포 조건을 확인하지 못했기 때문입니다. 아래 수치는 누구나 같은 도구로 자기 파일에 다시 돌려 볼 수 있습니다.

## 1. 받은 것

| 파일 | 내용 |
|---|---|
| `DESIGN.md` | 라이트 테마. 738줄, 35.6KB. 앞의 413줄이 머리말(YAML 토큰), 나머지가 설명 글 |
| `DESIGN-DARK.md` | 다크 테마. 구조는 같고 색 13개와 일부 설명만 다름 |
| `preview.html`, `preview-dark.html` | 토큰을 화면으로 그린 미리보기. 색, 글자, 버튼, 카드, 폼, 예시 화면 9종 |
| `tailwind-extend.json`, `tailwind-extend-dark.json` | Tailwind 설정에 붙여 넣는 색, 글꼴, 글자 크기, 간격 |

머리말에 들어 있는 것: 색 13개, 글자 24종, 간격 12단계, 모서리 1개(0px), 컴포넌트 32개와 예시 컴포넌트 10개.

## 2. 진단 결과

```
node scripts/design-check.mjs (받은 DESIGN.md)

  1층 겉모습  ■■■■  4/4
  2층 행동  □□□□□□□□  0/8
  3층 검증  ■■■□□□  3/6
     빠짐: 글자색과 바탕색 대비 (컴포넌트 34개 중 미달 5개)
     빠짐: 모호한 표현 0곳 (3곳)
     빠짐: 알려진 빈칸을 적어 둠
```

다크 파일도 4/4, 0/8, 3/6 입니다(대비 미달 6개). 공개 파일 84개를 쟀을 때와 같은 모양입니다. 겉모습은 가득, 행동은 0.

## 3. 잘 된 것

- **값이 숫자로 적혀 있습니다.** 글자마다 크기, 굵기, 행간, 자간이 있고 컴포넌트마다 높이와 안쪽 여백이 있습니다.
- **토큰 참조가 끊기지 않습니다.** 글 안의 `{colors.primary}` 같은 참조 364곳이 모두 머리말의 값으로 이어집니다.
- **라이트와 다크가 한 쌍입니다.** 구조와 이름이 같아서 색만 갈아 끼우면 됩니다.
- **근거를 밝힙니다.** 어느 페이지(홈, 블로그 목록)를 보고 썼는지 적어 둡니다.
- **스스로 한계를 적습니다.** 컴포넌트 설명 첫머리에 hover 상태를 기록하지 않았다고 적고, 44px 보다 작은 요소 두 가지에는 터치 여백을 더하라고 경고합니다.
- **금지 사항 7개**가 이름을 붙여 적혀 있습니다(둥근 모서리, 두 번째 강조색, 넓은 카드 간격 등).

분위기와 겉모습 값을 가져오는 출발점으로는 충분히 쓸 만합니다.

## 4. 빠진 것

- **상태 규칙이 없습니다.** 빈 화면, 오류, 처리 중, 누를 수 없는 상태가 어떻게 보이는지 적혀 있지 않습니다. 입력창의 포커스와 필터 칩의 선택 상태 두 가지만 있습니다.
- **오류색과 경고색이 없습니다.** 공개된 정적 페이지에 나타나지 않았기 때문이라고 파일이 밝힙니다. 그래서 미리보기의 실패 알림과 실패 표시가 본문 글자색으로 그려져 있습니다.
- **문구 규칙이 없습니다.** 말투, 버튼 문구, 오류 문장의 형식이 없습니다.
- **접근성과 움직임 규칙이 없습니다.**
- **예시 컴포넌트 10개는 사이트에 없는 것입니다.** 가격표, 장바구니, 데이터 표 같은 일반 틀에 이 사이트의 색을 입힌 것이라고 파일이 밝힙니다. 우리 제품의 화면이 아닙니다.

## 5. 기계로 재 보니 나온 것

### 파일대로 만들면 대비가 부족한 컴포넌트

본문 글자의 기준은 4.5:1 입니다.

| 테마 | 컴포넌트 | 글자 / 바탕 | 글자 크기 | 대비 |
|---|---|---|---|---|
| 다크 | 강조 가격 카드 (예시) | on-primary / ink | | 1.14:1 |
| 라이트 | live-badge | live-green / live-green-tint | 10px | 2.29:1 |
| 다크 | category-tag, scroll-cue, site-footer | mute / canvas | 10~13px | 2.66:1 |
| 라이트 | category-tag, scroll-cue, site-footer | mute / canvas | 10~13px | 2.85:1 |
| 다크 | button-primary, button-submit | on-primary / primary | 15px | 2.91:1 |
| 라이트 | tag-badge | badge-ink / tag-fill | 9px | 3.66:1 |

다크의 강조 가격 카드는 미리보기 화면에서는 어두운 글자로 그려져 있지만, DESIGN-DARK.md 의 토큰은 밝은 바탕에 흰 글자를 가리킵니다. 에이전트가 파일만 읽고 만들면 글자가 보이지 않습니다.

### 작은 글자와 작은 버튼

- 12px 미만 글자 토큰이 24종 중 5종입니다: eyebrow 11px, form-label 11px, category-tag 11px, source-label 10px, badge 9px
- 높이 44px 미만인 누르는 요소가 4종입니다: 내비게이션 버튼 34px, 아이콘 토글 32px, 필터 칩 30px, 서비스 토글 40px

### 머리말과 본문이 다른 곳

머리말은 기계가 읽는 값이고 본문은 사람이 읽는 설명입니다. 사양은 머리말 값이 기준이라고 하는데, 다섯 곳이 서로 다릅니다. 미리보기 화면은 본문 쪽 값으로 그려져 있습니다.

| 컴포넌트 | 머리말 토큰 | 본문 설명 |
|---|---|---|
| button-text | 굵기 300 | 500 |
| lab-card 제목 | 18px | 17px |
| status-badge | 9px | 10px |
| live-badge | 굵기 600, 자간 1.5px | 굵기 700, 자간 1.2px |
| inquiry-type-tab | 굵기 300 | 500 |

### 확인할 수 없는 표현

"generous", "barely visible", "roughly 14px" 세 곳입니다. 숫자가 붙지 않아 지켰는지 답할 수 없습니다.

## 6. 읽는 법

밖에서 관찰해 만든 파일은 **사이트를 있는 그대로 적습니다.** 틀리게 적은 것이 아닙니다. 다만 사이트에 있던 약점도 함께 토큰이 됩니다. 대비가 낮은 보조 글자색, 9px 배지, 30px 칩이 "규칙"으로 굳습니다. 에이전트는 이 파일을 기준으로 삼아 같은 약점을 새 화면에 다시 만듭니다.

그래서 받은 파일은 **지금 모습의 기록**으로 읽고, 기준으로 삼을지는 사람이 정합니다.

- 유료와 공개 파일의 차이는 형식이 아니라 **대상**입니다. 내 사이트의 실제 값이 들어 있습니다.
- 채워지지 않는 곳은 같습니다. 상태, 문구, 접근성, 규칙의 이유.
- 이 수치는 파일에 적힌 값을 잰 것입니다. 실제 화면을 잰 것은 아닙니다.

## 7. 받은 파일을 우리 기준으로 바꾸는 순서

1. 받은 파일을 `00_inputs/reference/` 에 넣습니다. 이 폴더의 파일은 AI가 읽기만 합니다.
2. `/design-check 00_inputs/reference/DESIGN.md` 로 진단합니다.
3. 리포트의 "대비가 부족한 컴포넌트"와 "머리말에서 읽은 참고 수치"를 보고 **남길 값과 고칠 값을 사람이 고릅니다.**
4. 머리말과 본문이 다른 곳은 실제 화면을 열어 어느 쪽이 맞는지 정합니다.
5. 고른 겉모습 값만 우리 `DESIGN.md` 로 옮깁니다. 예시 컴포넌트(이름이 `ex-` 로 시작)는 옮기지 않습니다.
6. 상태 규칙과 문구를 씁니다. 아직 정하지 못한 것은 "알려진 빈칸"에 적어 에이전트가 지어내지 않고 묻게 합니다.

붙여 넣는 문장은 `PROMPTS.md` 의 4교시 "선택 D"에 있습니다.
