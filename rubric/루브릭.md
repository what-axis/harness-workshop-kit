# 화면 채점 루브릭 — 모두의회의실

리뷰어 에이전트가 이 표로 화면을 채점한다. **총 100점, 통과선 85점. 단, ⛔ 표시 항목은 하나라도 0점이면 총점과 무관하게 미통과.**

C·D 섹션은 비어 있습니다 — 오늘 워크숍에서 여러분이 채웁니다. (C는 오전 Define에서 만든 가설 검증 항목, D는 Discover에서 뽑은 내 판단 기준)

## A. 접근성 (30점) — 기준: design/DESIGN.md §6

| # | 항목 | 배점 | 채점 방법 |
|---|---|---|---|
| A1 ⛔ | 텍스트 대비 4.5:1 이상 (18px+/700은 3:1) | 8 | 코드의 색상값으로 대비 계산. 위반 요소마다 -2 |
| A2 ⛔ | 터치 타깃 44×44px 이상, 타깃 간격 8px 이상 | 8 | 버튼·링크·칩의 크기/패딩 확인 |
| A3 | 인터랙티브 요소는 시맨틱 태그 (`<button>`, `<a>`) | 6 | div/span에 onclick류 발견 시 위반 |
| A4 | 상태·의미를 색+텍스트 병행 전달 | 4 | 색만으로 구분되는 요소 확인 |
| A5 | `lang="ko"`, 제목 계층(h1→h2→h3), 대체 텍스트 | 4 | 마크업 구조 확인 |

## B. 디자인 시스템 준수 (30점) — 기준: design/DESIGN.md §1~§5

| # | 항목 | 배점 | 채점 방법 |
|---|---|---|---|
| B1 | 컬러: 정의된 토큰 값만 사용 | 6 | 코드의 hex 값을 토큰표와 대조. 미정의 색마다 -2 |
| B2 | 타이포: 정의된 5단계만, 13px 미만 없음 | 6 | font-size 값 전수 확인 |
| B3 | 간격 4px 그리드, 좌우 패딩 20px | 5 | margin/padding 값 확인 |
| B4 | 컴포넌트 명세 준수 (버튼 52px·radius 12, 칩, 슬롯, 입력, 배지) | 8 | §4와 요소별 대조 |
| B5 ⛔ | 상태 4종(빈·로딩·오류·권한) 규칙 준수 — 해당 화면에 필요한 상태가 존재하고 §5 형식을 따름 | 5 | §5와 대조. 필요한 상태 부재 시 0점 |

## C. 가설 검증 (20점) — ✍️ Define 실습에서 채우기

오전에 세운 가설이 화면에서 실제로 구현됐는지 확인하는 항목. "가설: 필터 우선 탐색이 30초 예약을 가능케 한다" → "C1: 첫 화면 최상단에서 시간·인원·장비 필터에 탭 1회로 도달 가능한가 (8점)" 처럼 **화면에서 확인 가능한 문장**으로 쓴다.

|---|---|---|---|
| C1 | ✍️ | ✍️ | ✍️ |
| C2 | ✍️ | ✍️ | ✍️ |
| C3 | ✍️ | ✍️ | ✍️ |

## 채점 리포트 형식 (리뷰어 에이전트용)

- 화면별로 A~D 항목 점수 + **근거(해당 코드 발췌 또는 요소 명시)** + 총점/통과 여부
- 미통과 항목은 '무엇을 어떻게 고치면 되는지' 수정 방향 1줄씩
- 근거 없는 감점 금지. 루브릭에 없는 항목으로 감점 금지 (새 기준이 필요하면 "루브릭 추가 제안"으로 분리 기재)
